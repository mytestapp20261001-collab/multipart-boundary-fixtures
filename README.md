# Multipart boundary fixtures

Reproduce a multipart boundary collision or missing closing delimiter locally.
Useful for testing the framing generated by upload code without uploading any data.
Python 3.12+, standard library only. Payload bytes never appear in CLI output.

## Run

From this directory:

```sh
python3 tool.py --input examples/good.json --pretty
python3 tool.py --input examples/bad.json --pretty  # expected exit 1
python3 -m unittest -v
```

The good fixture has two parts and one closing delimiter. The bad fixture places
its boundary at the start of a payload line and omits the closing delimiter.
`--input -` accepts stdin; `audit(dict)` returns the same stable JSON result.
Exit 0: framing passes this subset; 1: modeled framing/collision findings;
2: malformed or out-of-range input. No network requests or file writes occur.

## Inputs and output

Synthesize mode requires `mode: "synthesize"`, `boundary` and `parts` (1..32 UTF-8
strings, each <=8192 characters, <=128 KiB encoded in total). Optional `closing`
(boolean, default true) and `newline` (`crlf`, default, or deliberately invalid
`lf`) create failure controls. The builder inserts a text/plain UTF-8 Content-Type
for every part. Payload line starts are preflighted for the boundary prefix,
including LF-only lines that could confuse a tolerant consumer.

Inspect mode requires `mode: "inspect"`, `boundary`, and `wire_base64` (strict
base64, decoded <=128 KiB). These keys cannot be mixed with synthesize-only keys.
It reports byte offsets for relevant framing findings, part-delimiter/closing counts, wire length and
SHA-256, not body bytes. `build_fixture(boundary_bytes, parts_bytes, closing=True,
newline="crlf")` is a local library helper for obtaining synthesized bytes;
`inspect_wire(boundary_bytes, wire_bytes)` returns framing findings and counts.
Use `audit` to enforce schema and size bounds around these low-level helpers.

Boundary parameters follow the RFC 2046 character/length rule (1..70 ASCII
characters, no trailing space), not the surrounding Content-Type quoting grammar.
JSON input is capped at 256 KiB. Unknown or duplicate JSON keys are rejected.

## Deliberate limits

This is a framing subset with no preamble or epilogue. Delimiters require CRLF;
the last close may omit its entire final CRLF; a dangling CR is not valid framing.
Bare CR bytes inside a binary payload do not create delimiter line starts. Transport padding (space/tab) is accepted.
Regular parts require a CRLF header/body separator with <=8192 header bytes;
headers themselves are not parsed. Headerless parts are supported.
Boundary-prefix lines with extra suffixes are flagged conservatively rather than
accepted as payload. No nested MIME, transfer encoding, form names, filenames,
Content-Type semantics, parser differential guarantee, malware detection, or
server acceptance is implemented. Binary body content is not normalized. A
passing framing audit cannot prove an upload is safe or accepted by any server.
The helpers do not enforce authorization and do not perform any upload.
